# TinyBase Application Guide

This project was generated by `create-tinybase`. Preserve its working data
lifecycle while adapting the application to the user's requirements.

## Selected Architecture

- **Application**: todo list
- **Language**: TypeScript
- **UI**: React
- **Store**: MergeableStore
- **Persistence**: SQLite WASM
- **Synchronization**: Cloudflare Durable Objects
- **Schemas**: enabled

The generator uses a MergeableStore so synchronization can be added or removed
without changing the application data API. Do not replace it with a regular
Store unless merge metadata and future synchronization are intentionally
unnecessary.

The Store is loaded before automatic saving starts. Preserve that ordering so
initial in-memory data does not overwrite persisted data during startup.

## Key Files

- `README.md` explains how to run the generated project.
- `client/src/Store.tsx` configures the primary
  TinyBase Store.
- The primary Store file also initializes persistence.
- The primary Store file also initializes synchronization.
- `client/src/App.tsx` contains the main application UI.
- `client/src/config.tsx` contains synchronization configuration.
- `server/index.tsx` contains the synchronization server.

## Working Method

1. Read `README.md` and the primary Store file before making changes.
2. Keep application data in TinyBase rather than duplicating it in UI state.
3. Use the existing React bindings and generated component patterns.
4. Keep persistence and synchronization setup separate from application UI.
5. Run the client build after edits.
6. Run the server build when server code changes.

## Verification

From `client`, run:

```sh
npm run build
```

Change data in the running app, reload the page, and confirm the change remains.
Open the same room URL in two clients, change data in one, and confirm the other
updates. Test reconnection if synchronization behavior changes.
