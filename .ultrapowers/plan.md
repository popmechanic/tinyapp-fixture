# tinyapp-fixture — every exam proves only itself

**Grammar:** claims-v1

**Claim:** When I run one exam it costs seconds, not minutes, because no exam runs any other exam, the linter or the typecheck for it. (elicited)
**Summary:** This plan strips every state exam of the commands it ran to re-check other exams, the linter's tests, the app's checks and the typecheck, so each exam proves only its own claim through the helper it already imports. It exists because those re-checks made one exam cost up to ten minutes and the run's final full suite grow from about two minutes to nineteen over four runs, and one such re-check was already failing before the last run started and killed a task. The user gets exams that answer in seconds, a suite that runs once at the end, and no task dying on another exam's failure.

**Goal:** Remove every child-runner call from the 21 exam files that carry one, keep each file's own in-process legs, and leave the run-wide checks — `lint:ui`, `typecheck`, `lint:state` — to the driver's `Check:` lines and the fold's suite, where regression belongs. The reading behind it: 21 of the 31 files under `tests/state-exams/` spawn a child at BASE (measured 2026-09-17 at `42d19c50aaecd92f13367b2b97324a3013bb62fb`), and run-24's task 2 died `proof-red` on `styled-page.test.ts` leg (f), whose child command was red at BASE on the sandbox.

**Tech Stack:** Bun 1.4.2, TypeScript, TinyBase, `tinyapp-exam` (`packages/tinyapp-exam`), `bun test`
**Exam command:** bun test {paths}
**Spec:** none — authored from the operator's decision of 2026-09-17 and the reading in each task's Context.

**Parallelization rationale:** One wave, width 2. The 21 offending files are split into two file-disjoint sets — Task 1 the nine files that spawned test runners and CLIs (85 of the 143 matching lines), Task 2 the twelve that mostly spawned greps and typechecks (58 lines) — and the two tasks share no symbol, so neither waits on the other; the run-wide greens are the Global `Check:` lines, paid by each task in its own clone. No chain.

## Global Constraints

- Check: bun run lint:ui
- Check: bun run typecheck
- Check: bun run lint:state
- Check: git diff --quiet $ULTRA_BASE -- client server state-exams packages package.json bun.lock
- The app, its snapshots and the packages do not change: every edit of this plan lands under `tests/state-exams/`, and the `Check:` above is the fence that says so.
- One claim, one prover: an exam proves its own claim through imports and calls on the helper (`runStateExam`, `runPersistenceExam`, `renderStatic`, the store module, `readFileSync` of a repository file) and never spawns a process. A leg that only proved "some other exam, a package's tests, the linter or the typecheck still passes" is deleted, because the fold's suite proves that once.
- Deletion is per leg, never per file: a leg whose assertion ran in this process at BASE is kept as it was, and no file loses its `stateExam(` or `persistenceExam(` registration. A reviewer reads a file that lost an in-process leg, or a file reduced to its registration, as a blocking finding.
- A spawned `grep`/`sed` over an app file (`client/`, `packages/*/src`, `AGENTS.md`, `README.md`, `.gitignore`, `package.json`) may keep its predicate as an in-process read of that file; a spawned `grep` over another test file is deleted — that is the text pin on a sibling file that folds away (run-13). A leg that never spawned stays as it is, whatever it reads.
- Every exam file's own legs still pass when the file is run alone: `bun test tests/state-exams/<file>.test.ts` exits 0 for every file either task touched, and elapsed seconds are a reading on the record, never a threshold a leg asserts.
- Hermetic: no exam opens the network; `withContract` still holds every action.
